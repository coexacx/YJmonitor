## 安全审阅与扫描

- Gitleaks 源码扫描：0 项凭据泄漏。
- Certbot 环境及测试工具依赖的 pip-audit：0 项已知漏洞。初始虚拟环境附带旧 pip 的告警已通过升级独立环境解决，安装流程要求 pip >= 26.2；不更换系统 Python。
- Bandit：原始结果为 3 项中风险、22 项低风险，均逐项审阅。中风险对应已有 IP 入口监听、固定 GitHub HTTPS 地址读取，以及证书工具代码目录的 0755 权限；该目录不保存 Token 或私钥。低风险主要为使用 subprocess、固定 PATH 命令和语法解析变量被误判为密码。子进程使用参数数组；域名、路径、端口和配置归属均做检查，没有 shell / eval 执行用户输入。
- Cargo Audit：仍有既有 RUSTSEC-2023-0071（rsa）告警。当前受管私钥只使用 Ed25519，RSA 用于 SSH 主机公钥校验；未引入 RSA 私钥解密或签名路径。本轮没有变更 Rust 依赖。详见 [安全边界](RUST-SECURITY.md)。
- 新增测试覆盖域名注入、符号链接与可写目录拒绝、同名/通配/正则站点冲突、私钥权限、Token 不进入命令行、限制证书客户端环境、证书域名与有效期分别校验、申请失败和健康检查失败回滚、软件仓库文件回滚，以及手动修改后的卸载保护。
- 例行续期检查在证书未变化时不重载 Nginx，减少不必要的连接影响。HTTPS 配置与面板更新共用更新互斥锁，避免同时更换入口和程序。

源码与发行包使用原有签名流程；私钥、管理员口令、实际节点数据和 Cloudflare Token 均不进入发行物。生成的 SHA256SUMS.json 如触发通用密钥规则，必须逐条核对为实际文件摘要，不能整类忽略密钥检测。
