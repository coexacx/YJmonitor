# 终端链路与流控

浏览器终端与文件操作分别建立 WSS 连接，都使用原来的 /api/terminal 路径，不需要修改 Nginx。旧浏览器缓存仍可使用原合并协议；升级后刷新页面即可启用独立文件连接。

| 内容 | 调度方式 |
| --- | --- |
| 键盘输入和窗口尺寸 | 独立有界输入队列，按序发送，不重放未确认命令 |
| Shell 输出 | 独立读取任务、有限输出队列和浏览器 ACK 窗口 |
| 文件浏览和编辑 | 独立浏览器 WSS 与按需 SSH 连接 |
| 文件上传下载 | 文件 WSS 中独立工作队列与另一条 SSH 连接，分块传输 |
| 资源查询 | 独立 SSH 连接及回复队列，不等待浏览和上传任务 |
| SSH 保活和重新协商 | 每条 SSH 连接分别计时，重新协商有独立截止时间 |
| WSS 心跳和流控 ACK | 控制队列优先调度，读取端不等待文件操作完成 |
| Agent 指标 | 独立采集任务、控制发送队列，容量有界 |

Agent 仍通过一条经过 TLS 加密及节点令牌认证的 WSS 与主控通信，内部复用受限通道。键盘和输出是 SSH 的全双工方向，并非六条独立物理网络。网络完全拥塞或断网仍会影响同一服务器上的连接；此设计用于避免应用队列互相堵塞，并保留合理的超时与内存边界。

文件 WSS 使用新的一次性终端票据，并绑定已连接终端的文件会话、原管理员登录、认证版本与节点。每个终端只允许一条附属文件连接；单独断开文件连接不结束 Shell，前端有限重试，不自动重放保存或上传请求。文件队列按既有续传校验恢复。

关闭终端标签、退出登录、撤销设备、修改账号认证信息，或到达绝对登录有效期，会撤销相关通道。浏览器整个终端异常断线仍按原规则保留 Shell 五分钟，仅原登录可恢复；主动关闭即结束。

Agent 0.2.3 将心跳、监控、ACK 与批量 SSH 数据拆成有界发送队列。SSH 关闭消息保持在已排队数据之后，避免先关闭通道而丢失输出。旧 Agent 协议兼容，更新后生效。
