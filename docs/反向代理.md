# 配置 HTTPS 反向代理

0.10.3 起，一键脚本只安装 Rust 主控及系统服务。安装结束显示 http://服务器IP:19281；可以登录查看面板。接入 Agent、浏览器终端和文件操作需要先完成本页的 HTTPS 配置，节点仍使用 WSS，不提供明文 WS 降级。

脚本不会安装或修改 Nginx、申请证书、改动已有网站、放行安全组。已有 80/443 网站可以继续运行。HTTP 初始入口传输未加密，首次配置也可以通过 SSH 本地隧道完成；公网正式使用请配置 HTTPS。

## 1. 准备域名和证书

以 probe.example.com 为例，将 A 记录解析到主控服务器；有 AAAA 记录时也需正确指向该服务器。为此域名取得有效的证书，并准备 fullchain.pem 与 privkey.pem。宝塔用户可在该站点的 SSL 页面申请和启用证书。

一键安装默认服务端口是 19281，自定义安装端口时，下文的 19281 应一起替换。

## 2. Nginx 配置

下面是一个完整的 HTTPS server 示例。放到该站点的 Nginx 配置中，修改域名与证书路径。已有站点配置时保留原来的 listen、server_name、证书和 ACME 验证段，只替换该站点的代理与 location 配置，避免重复定义。

~~~nginx
server {
    listen 443 ssl;
    server_name probe.example.com;

    ssl_certificate     /你的证书目录/fullchain.pem;
    ssl_certificate_key /你的证书目录/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    autoindex off;
    client_max_body_size 24m;
    client_header_timeout 10s;
    client_body_timeout 60s;
    send_timeout 60s;
    keepalive_timeout 30s;

    location / {
        proxy_pass http://127.0.0.1:19281;
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
~~~

公开访问全部交给 Rust 程序，没有 PHP 配置，也不需要把任何目录映射为公开的静态目录。状态目录不能作为 Nginx root。WebSocket Upgrade 头不能省略，否则监控和终端无法建立连接。

如果同机还有其他网站，只修改此域名的 server，不覆盖 nginx.conf，不停用整机 Nginx。先运行 nginx -t，成功后再 reload。宝塔可使用面板中的配置检测和重载。

HTTP 80 可以自行添加跳转到 HTTPS 的 server，同时保留证书续期所需的 ACME location。本程序和安装脚本不接管证书续期。

## 3. 设置面板地址

在服务器终端运行：

~~~sh
sudo yuji-probe
~~~

选择「7 设置访问地址」，填写 https://probe.example.com，服务端口保持 19281。脚本只修改自己的 systemd 服务和更新器配置，不修改 Nginx；HTTPS 模式下主控改为监听 127.0.0.1。确认浏览器通过 HTTPS 可以登录，再添加监控服务器。

此菜单用于空面板首次设置入口；已有节点时使用后台的备份、恢复及迁移流程同步新地址，避免只改主控入口造成 Agent 失联。已有宝塔手动部署不采用一键脚本的固定路径，请使用下一节的手动配置方式。

## 4. 宝塔配置应分别放在哪里

- 站点配置文件的 server 内：listen、server_name、SSL、autoindex、client_max_body_size 和各项超时。
- 代理 location 可以写在该 server 内，也可以放到宝塔为此站点引入的「伪静态」文件中；后者虽然叫伪静态，本质上仍是 server 内的 Nginx include。两处只能选一处，不能重复。
- 使用「伪静态」时只放上面 location / 的整段，不能放 server 外层，也不要把 listen 或证书配置放进去。
- 删除此站点的 PHP 引入、旧的 try_files 与重复 location /；保留宝塔的证书及 ACME 验证配置。不要删除其他域名的配置。

## 5. 手动部署的 systemd 参数

Rust 二进制的原有参数仍然兼容：

~~~ini
ExecStart=/你的程序目录/bin/probe-linux-amd64 -web -state /你的私有目录/control -listen 127.0.0.1:19281 -origin https://probe.example.com
~~~

ARM64 使用 probe-linux-arm64。私有目录、程序目录和独立系统账户的权限设置见 [部署教程](Nginx-Rust部署教程.md)。仅 native -web 模式可以使用公网 HTTP 监听；旧 PHP 网关模式仍限制回环地址。HTTPS 的 Agent 与终端入口只接收同机反向代理转来的连接。

## 常见问题

- IP:端口无法打开：查看 systemctl status yuji-probe；确认使用安装结束显示的端口，云安全组允许该端口。脚本不会修改防火墙。
- 域名页面提示地址不正确：确认 Host 转发完整（带非默认端口），并检查管理菜单内保存的完整 URL。
- 502：确认 Nginx 代理端口与 systemd 的 -listen 相同，主控正在运行。
- 可以登录但无法添加节点：确认菜单中已设置 HTTPS URL，证书受信任，节点能访问此域名。
- 非同机反向代理：当前信任边界为同机回环代理，不接受把远程代理请求头当作客户端身份；请部署同机 Nginx。
