# 服务器管理与批量升级

适用于 Rust 主控 0.11.4 起。部署方式不变，Agent 仍为 0.2.3。最多管理 1000 台服务器；管理员列表与版本管理每页显示 50 台，看板每页显示 60 台。

## 服务器 → 服务器管理

- 使用全部 / 在线 / 离线切换；待接入归入离线。
- 搜索名称、IPv4 / IPv6、分组或供应商，可与分组、供应商及到期状态同时筛选。
- 3 天内到期指未来 72 小时内，已过期单列；不依赖续费提醒是否开启。
- 状态按钮数量随其他筛选条件变化，列表显示匹配数量 / 全部数量。
- 实时刷新和切换后台菜单保留当前筛选，重置筛选恢复全部。
- 筛选时隐藏看板排序，避免误改隐藏服务器的顺序。
- 连接信息显示最后有效上报、持续离线时长和近期通讯错误。「排查信息」汇总时间、SSH 地址、Agent 版本、最近部署及管理任务。
- 连接错误只是观测记录，不能据此断定服务器已关机。缺少断开事件时依据上报超时估算离线开始；待接入不会显示虚构的离线时长。

## 版本管理

勾选在线服务器后点击「升级所选」。页面会要求近期身份验证，启用二步验证时同时验证动态码或恢复码。主控使用固定签名发布源，不接收浏览器提供的安装地址。

一次最多 1000 台，共享两个升级 / 部署并发名额。任务在主控保存，关闭页面继续执行，重新进入可查看等待、执行中、完成与失败。主控重启后继续未完成任务；失败项不会无限自动重装，可单独重试或点击「重试失败项」。离线、移除中、已有管理 / 部署任务或架构尚未识别的节点不可勾选。提交瞬间状态发生变化时逐台返回原因。

配套 Agent 已是同版本时仍可重新应用签名二进制，便于修复安装。单台回退与迁移重试入口保留。任务完成表示远端校验安装并通过连接检查，不代表升级期间终端完全不中断。

## 1000 台规模部署

主控进程会在现有硬限制内将文件描述符软限制提升至 8192，新安装的 systemd 服务也设置 LimitNOFILE=8192。主控仍使用有界部署并发，不会一次创建 1000 个 SSH 升级连接。建议 Nginx 每 worker 至少 worker_connections 4096（每条反向代理 WSS 会占用前后两条连接），确保系统文件描述符上限足够；已有 Nginx 全局配置需要部署者核对，面板不会覆盖其他站点配置。

1000 台是应用数量上限，不是任意配置服务器的性能保证；实际所需资源取决于网卡 / 磁盘数量、上报频率、访问量和终端使用。


### 最低配置目标与实测

建议最低部署配置：1 vCPU、1024 MB 内存、10 GB 系统盘，使用预编译安装包。无需 PHP、数据库、Node.js 或 Rust 编译器。主控 systemd 内存上限保持 512 MiB；管理员与看板分页，隐藏看板不重复绘制，节点列表按秒复用已序列化数据。

2026-10-08 在开发机通过 cgroup 将主控与独立 Nginx 合计限制为 1 核 CPU / 768 MiB，留出 256 MiB 系统预算。1000 个同一 NAT 出口的模拟 Agent 每秒通过 WSS 上报，50 个客户端每 5 秒同时刷新看板，预热后采样 60 秒：

| 指标 | 结果 |
| --- | --- |
| 最终在线 / 最新上报对齐 | 1000 / 1000 |
| 看板请求 | 600 次成功，0 错误 |
| Agent 异常掉线 / OOM | 0 / 0 |
| 主控平均 CPU / RSS 峰值 | 单核 33.4% / 41.9 MiB |
| 主控 + Nginx 平均 CPU | 单核 55.4% |
| 主控 + Nginx 内存峰值 | cgroup 160.9 MiB，包含内核计费缓存与连接内存 |
| 看板 P50 / P95 | 173.1 / 269.2 ms |

主控 amd64 二进制约 14.1 MiB；完整包解压约 42 MiB，包含两种架构、源码和许可证。10 GB 系统盘可作为轻量 Linux 部署目标，系统、Nginx、更新回退、日志和备份需要另外占用空间，更新前保留至少 1 GB 空闲更稳妥。备份设置按需保留有限份数。

这次是共享开发机上的 CPU / 内存限额短测，未创建 1 GB 内存、10 GB 磁盘的独立虚拟机，也未同时开启大量 SSH 或大文件传输。CPU 型号、节点磁盘 / 网卡数量、访问量及网络带宽会影响结果；它证明此负载在预算内运行，不代表任意工作负载的长期保证。详细结果见 [原始指标](performance-0.11.4.json)。Nginx 参数位置见 [反向代理连接容量](反向代理.md#接近-1000-台时的-nginx-连接容量)。
