# Rust 独立仓库迁移（0.10.1）

独立仓库：[coexacx/YJmonitor](https://github.com/coexacx/YJmonitor)。本版从原项目 0.10.0 拆分，主控版本为 0.10.1，Agent 保持 0.2.2。

## 本次变化

安装器、主控更新检查、主控更新下载及 Agent 下载统一指向新仓库的 v* 正式 Release。安装包不包含 PHP 入口或 PHP-FPM 配置。独立仓库默认发布文件为 yuji-probe-rust-0.10.1.zip；源码下载与预编译安装包仍分开提供。

数据格式、节点认证、WSS 协议、SSH/SFTP 通道及发布验签公钥保持兼容。Agent 二进制复用已校验的 0.2.2，不需要因仓库拆分重新安装被控或修改节点密钥。原项目的 PHP 发行版保留在原仓库。

更新器使用独立的路径及服务：
- 程序：/usr/local/lib/yuji-probe-rust-updater/
- root 配置：/etc/yuji-probe-rust-updaters/
- 回退快照：/var/lib/yuji-probe-rust-updater/
- systemd：yuji-probe-rust-update-实例名.path / .service

旧 PHP 更新器不会被新更新器覆盖。运行目录和服务名仍以各自安装配置为准。

## 新安装

使用 [部署教程](Nginx-Rust部署教程.md) 中的新仓库安装命令，或下载本仓库完整 ZIP 按宝塔 Nginx 反向代理步骤部署。不需要 PHP-FPM、数据库或本机编译。

## 已安装原仓库 rust-v0.10.0

先导出加密备份，并在站点之外保存完整程序、私有状态和 systemd/Nginx 配置。主控重启会中断当前管理连接；先结束终端和文件传输。

1. 从新仓库下载完整 ZIP 和校验文件，按部署教程验证并解压到临时目录。保留原数据，不能用新包中的空 storage 覆盖。
2. 记录当前 Rust 服务名、程序目录、私有状态目录、监听端口与 -origin。停止旧实例的更新监听，再停止这一 Rust 服务；不要停止其他网站。
3. 在原程序目录中替换程序、页面资源、源码和运维脚本，保留原私有状态。保持程序由 root 持有，服务用户只写私有状态；主控二进制可执行。
4. 启动原服务，核对版本 0.10.1、原账户登录、节点上线与 SSH/SFTP。域名不变且完整保留状态时，Agent 自动重新连接。
5. 用新包的 ops/update-panel.py 重新注册本实例的更新器。该步骤只配置新更新服务，不重建站点或管理员。
6. 检查“版本管理”的发布链接为 coexacx/YJmonitor，随后按新仓库更新。

以下是手动教程默认路径的注册示例，必须换成自己的实际目录、服务和域名：

~~~sh
python3 /opt/yuji-probe-rust/ops/update-panel.py --configure \
  --name rust-main --root /opt/yuji-probe-rust \
  --state /var/lib/yuji-probe-rust/control \
  --service yuji-probe-rust.service \
  --origin https://probe.example.com --listen 127.0.0.1:19282 \
  --distribution rust
~~~

原仓库的旧监听通常名为 yuji-probe-update-实例名.path。只停用本次迁移实例对应的监听，保留其他 PHP 或 Rust 实例的更新器。新监听名带 rust-update 前缀；不要让两套更新器写同一份状态。

首次手动迁移的回退使用迁移前保存的程序、私有状态及配置；新更新器只能回退它之后实际保存的快照。若回退到 0.10.0，同时停用新监听并恢复原监听配置。不要同时启动两套主控写同一份状态。

PHP 版跨架构迁移另见部署教程对应章节，不能把 Rust 包交给 PHP 版更新器。 若旧站点保存了离线 Agent 发布缓存，应按教程归档旧版缓存，避免旧 `stable.json` 被新版签名版本检查拒绝。

## 验收与性能范围

本次修改集中在仓库、版本及发行配置；终端、监控和文件管理逻辑沿用 0.10.0。基线资源比较见 [0.10.0 验收报告](验收-0.10.0.md)，不将历史数据表述为本次重跑。

本次核对包括主控测试、前端测试、脚本检查、仓库地址白名单、两种架构构建、签名与文件哈希、0.10.0 → 0.10.1 更新和回退、安装保护、现有账户/节点保留，以及发布后匿名下载。具体机器验收结果随 Release 的 verification-0.10.1.json 提供。

上游 RSA 告警继续披露，见 [安全说明](RUST-SECURITY.md)。本次没有增加依赖或变更加密算法。ARM64 为交叉编译，本轮真机为 amd64；未在全新公网主机重新申请 ACME 证书，也不重复声称长期稳定性验证。
