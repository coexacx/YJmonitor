# Telegram 群组通知

管理员进入「Telegram 通知」，先保存 BotFather 提供的 Bot Token，再在「群组通知」填写负数群组 ID 并启用。把机器人加入目标群组并设置为管理员，然后点击「验证并保存」。

主控调用 Telegram 官方 getMe、getChat、getChatMember 接口，确认机器人身份、目标为群组或超级群组，且机器人在该群组中拥有管理员权限。频道、私人聊天、普通成员、已退出和被移除的机器人均不能通过群组设置。群组名称只作为文字显示。

群组自动消息仅包括服务器上线、连续离线和恢复。管理员登录、续费、供应商、SSH 凭据等不会作为群组事件发送。离线持续 20 秒后生成提醒，恢复消息与首次上线使用不同标题；新启用时以当前状态作为基线，不一次性发送全部服务器状态。公开服务器名称和站点名称会出现在通知中。

「发送群组测试」会发送明确标注的测试消息，每 60 秒一次，不伪造节点故障。通知包含面板入口按钮。群组与原接收人各自保存发送状态和重试事件，一方等待重试不会阻塞另一方。自动事件保留各自的先后次序，通知使用有限重试，网络在 Telegram 已接收但回包丢失时仍可能重复投递。

个人接收人开关不会关闭群组通知。两者共用加密保存的 Bot Token；修改或清除 Token 后，群组通知暂停，需重新验证并启用。群组发送前会再次检查机器人管理员权限，权限被撤销后不会继续发送，错误在后台展示。恢复权限后可再次保存并发送测试。

Token 不返回浏览器、不写入日志或操作记录。请求只发往固定 Telegram HTTPS 接口，不允许自定义 API 地址，禁止重定向，并限制请求时间和响应大小。访问设置需要管理员认证；修改和测试还需 Origin / CSRF 验证。

部署服务器需要能连接 Telegram API。连接失败时先检查服务器的出站网络，再核对群组 ID、Bot Token 和群组权限。

接口依据：[Telegram Bot API：getChatMember](https://core.telegram.org/bots/api#getchatmember)、[getChat](https://core.telegram.org/bots/api#getchat)、[getMe](https://core.telegram.org/bots/api#getme)。
